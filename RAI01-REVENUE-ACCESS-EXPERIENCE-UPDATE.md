# Revenue and Access Integrity UI preparation — 2026-10-11

Four authenticated workspaces now include a clearly labeled local simulator preview. Members can review example post-checkout entry, active-visit rescan and uncertain-checkout states. Reception can inspect sample exception reasons without gaining a financial override. Managers can explore illustrative tariff bands, independent financial approval and potential discrepancy cases. Technical staff see the read-only boundary between command delivery and physical evidence.

The preview uses the existing Persian, responsive light/dark design system. Publication, payment confirmation, wallet adjustment and physical control remain disabled. Sample prices and cases are unrelated to real members, branches or transactions. The browser review used a disposable local stack with 29 accepted migrations; it tested the four role routes at mobile, tablet and desktop widths, plus permission denials, keyboard navigation and blocked external internet. No product mutation or external request was observed.

The owner's pricing, offline-admission, no-app confirmation and dual-control policies are documented for future Main integration. Main must publish and authorize the corresponding versioned APIs before any financial or gate workflow can be connected. This source candidate was not deployed.
